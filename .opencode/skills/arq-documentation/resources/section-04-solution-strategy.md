# Section 4: Solution Strategy

## Goal

Summarize the fundamental decisions and solution strategies that shape the architecture: technology choices, decomposition pattern, how quality goals are met, and the architectural style.

## Guidelines

- This section is a SUMMARY — a quick-reference for understanding the "why" behind the architecture
- Details live in subsequent sections (Building Block View, Runtime View, Deployment View, ADRs); this section gives the overview
- Each row in the table should map a quality goal or problem to a concrete decision with rationale
- If a decision is not yet made, state the options being considered — do not leave it blank
- The table format (Quality Goal / Problem -> Decision -> Rationale) is the primary output
- Include the architectural style and main patterns (e.g., "modular monolith with event sourcing for audit trail")

## Template Section

Use the `## Solution Strategy` section from the template with:
- Decision table (Quality Goal / Problem, Decision, Rationale)

## Tips
- Explain the solution strategy as compact as possible (e.g. as list of keywords)!
- Describe the solution approaches as a table!
- Describe solution approaches in context of quality requirements!
- In the solution strategy, refer to concepts, views or code!
- Let the solution strategy grow iteratively / incrementally!
- Justify the solution strategy!
