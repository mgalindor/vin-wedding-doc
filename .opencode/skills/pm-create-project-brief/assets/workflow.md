# Project Brief Creation Workflow

**Very Important**: Follow these steps strictly and in order. Do NOT skip steps or proceed to a later step without completing the previous one.

---

- [ ] **Step 1 – Read kickoff documents**
  Infer the kickoff folder from the workspace organization. List all files in it and read each one completely. If the folder is empty (only `.gitkeep`), stop and ask the user to provide the kickoff information before continuing.

- [ ] **Step 2 – Read current project brief file**
  Infer the project brief filename from the workspace organization. Read it fully to understand its current state, existing front-matter, and which sections are already filled in.

- [ ] **Step 3 – Extract structured information**
  From the kickoff documents, extract and organize the following:
  - Project name, client name, and one-line project summary
  - Project overview (2–4 paragraphs)
  - Current situation and critical risks (challenges)
  - Objectives (at least 1, up to 5)
  - Outputs (tangible deliverables)
  - Outcomes (business value / results)
  - Out-of-scope items
  - Stakeholders (name, contact, role, company)
  - Team members (name, contact, role, company, responsibilities)
  - Timeline (start date, number of sprints, duration per sprint)
  - Assumptions

- [ ] **Step 4 – Present a summary to the user**
  Before writing anything, show the user a brief summary of what you extracted (project name, objectives, team, timeline). Confirm the user is satisfied before proceeding.

- [ ] **Step 5 – Write the Project Brief**
  Using [template-readme.md](template-readme.md) as the structural guide, replace all placeholders with the real project data and write the complete content directly into the project brief file. Keep the section structure intact. Do not remove any section.

- [ ] **Step 6 – Verify against checklist**
  Run through every item in [checklist.md](checklist.md) and confirm all are satisfied. If any item fails, fix the file before finishing.

- [ ] **Step 7 – Confirm completion**
  Notify the user that the Project Brief has been created/updated and highlight any sections that still require manual input (e.g., missing contacts or dates).
